# Compatibility and code review — 23 October 2026

Reviewed plugin commit `2f6c3996540b07b44f8cb1b5695fac6d66e2abc5` against AzuraCast
`main` at `19d68c47b1e4d569885ca7cf4c40609cbabefda7`, fetched for this review.
This document records the findings in the original commit. The fixes following
this review are summarized at the end; the findings below remain as the baseline.

The plugin is not ready for station deployment. Three blocking issues were found,
including two that the passing Liquidsoap type check cannot detect.

## Findings

### 1. High: the audio graph fails when started

Location: `liquidsoap/sidechain.liq`, `sweepers.sidechain`; called by
`liquidsoap/sweepers.liq`, `sweepers.mix`.

Running the existing Liquidsoap fixture, rather than only type-checking it, fails
on native Liquidsoap 2.4.5 with:

```text
Early computation of source content-type detected for source
ffmpeg.filter.audio.output.2 on clock audio.producer.4!
```

The process exits with status 2. No sweeper plan or API connection is needed to
reproduce it. A second fixture with a prepared synthetic sweeper fails the same
way. Plain audio and a single-output FFmpeg encode/filter/decode control both exit
successfully on the same runtime.

The three FFmpeg outputs and their decode/clock arrangement need correction.
Starting a station with this graph is not validated by `--check`. Confirm the fix
on the actual AzuraCast container as well as native 2.4.5, then render and inspect
audio with and without an overlay. The exact AzuraCast container was not run here.

### 2. High: the AutoDJ callback override is not connected

Location: `liquidsoap/sweepers.liq`, `sweepers.original_next_song` and the subsequent
`azuracast.autodj_next_song` definition.

AzuraCast defines `azuracast.enable_autodj` in its common runtime before the plugin
is included. That factory captures the original `azuracast.autodj_next_song`.
Redefining the function afterward does not change the captured binding. The
generated configuration still calls the original `azuracast.enable_autodj`.

A Liquidsoap 2.4.5 reproduction with the same declaration order prints:

```text
direct=wrapped
factory=original
```

Consequently, fixing the mixer alone will not enable planning: the native AutoDJ
continues using its original callback and does not populate `sweepers.plans`.

Integrate at a point that actually passes the wrapped callback to the request
source, preserving AzuraCast's native queue and fallback behavior. Add a runtime
assertion that the factory-created source reaches the planning callback; calling
the new function directly is insufficient.

Upstream reference: `util/docker/stations/liquidsoap/azuracast.liq`,
`azuracast.enable_autodj`; `backend/src/Radio/Backend/Liquidsoap/ConfigWriter.php`,
`writePlaylistConfiguration`.

### 3. High: installation uses the wrong plugin-mode variable

Location: `README.md`, Docker Compose installation example.

The example sets `AZURACAST_PLUGIN_MODE`. Current AzuraCast startup checks
`COMPOSER_PLUGIN_MODE` in `util/docker/web/startup_scripts/08_plugin_mode.sh`.
That script runs the Composer merge/autoload update needed for plugin classes.
The main application autoloader does not otherwise map this plugin namespace.

On a fresh installation following the example, plugin classes can fail to load
when `events.php` registers the subscriber. Change the documented setting to
`COMPOSER_PLUGIN_MODE: "true"` and test a clean container installation, including
dependency merging and route registration.

### 4. High: a stale editor can approve an intro for replacement audio

Location: `src/Controller/PanelController.php`, `saveIntro`; `frontend/App.vue`,
`saveIntro`.

Recording identity validation applies only when `$manual` is false. The browser
does not send the identity it reviewed. If a file is replaced after the editor
loads, saving approves the old timestamp against the replacement's current
identity and can also lock it against automatic correction.

Require the reviewed recording identity on manual saves as well as imports and
return HTTP 409 on a mismatch. Check it under the update boundary, rather than
merely attaching the latest identity to an old review. Include a test that opens
recording A, replaces it with B, then saves A's review.

### 5. Medium: abandoned reservations exhaust the sweeper pool

Location: `src/Service/Planner.php`, `plan` and `played`;
`liquidsoap/sweepers.liq`, failure, reset and late-activation branches.

Every unplayed plan reserves its jingle for up to 3,600 seconds. Only successful
playback changes its state. Skipping a song before the sweeper, live takeover,
late activation, a failed jingle resolution or a Liquidsoap restart does not
release the reservation. Repeating this across a small playlist can leave no
eligible sweepers until expiry, even though all files would fit.

Use explicit release/expiry tied to queue and playback lifecycle. Reserve future
plans without treating abandoned plans as pending for an hour. Also handle a
failed playback acknowledgement so it does not permanently lose rotation state
until timeout.

### 6. Medium: every next-song request resolves the entire sweeper catalogue

Location: `liquidsoap/sweepers.liq`, `sweepers.resolve_jingles` and its call from
the wrapped next-song callback.

All jingles are resolved sequentially, with a 15-second timeout each, before the
song request returns. This happens even before the PHP planner determines whether
the song has any usable intro. AutoCue's cache reduces analysis cost but does not
remove repeated request resolution, remote-media access or individual timeouts.

Twenty slow entries can therefore consume approximately five minutes of added
resolution time. This is outside the synchronous audio callback, but it can still
delay native AutoDJ readiness and cause fallback playback. The callback wiring
bug currently hides this path.

Cache resolved measurements by recording identity and relevant AutoCue/settings
revision, refresh separately, and use one bounded preparation budget. Skip
catalogue work for ineligible songs and ensure optional sweeper work cannot hold
up the next music request indefinitely.

### 7. Medium: intro value and review protection are not committed atomically

Location: `src/Controller/PanelController.php`, `saveIntro`;
`src/Service/Media.php`, `saveIntro`; `src/Service/State.php`, `update`.

The callback passed to `State::update` flushes the custom-field change to the
database before the JSON state file is written. If creating or writing that file
fails, the database change remains committed while identity, review status and
manual protection remain old or absent. The request fails, but part of the change
has already taken effect.

Use a transactional representation for the cue and its review metadata, or an
explicit recoverable commit/reconciliation mechanism. Add fault injection after
the DB flush. Atomic file rename alone does not cover the database operation.

### 8. Medium: displayed AutoCue timing can differ from playback

Location: `src/Service/Media.php`, `timing`.

The panel merges cached data with manual metadata using manual values as the
winner, then applies its own defaults through `Timing::fromArray`. Current
AzuraCast builds playback annotations in a different sequence: manual annotations
first, cached annotations afterward, with validation and station fade defaults in
`Annotations::processAutocueAnnotations`.

For example, when manual cue-in is 2 seconds and an existing cache supplies 0,
the panel can display 2 while the native annotation path supplies 0. Partial
manual metadata can also produce a null panel timing even though native defaults
produce valid playback annotations. This is an inconsistency in the plugin's
display contract; it is not a recommendation to change AzuraCast's precedence.

Build the display from the same native annotation path, and distinguish cached
or provisional information from metadata actually resolved for playback.

## Architecture and compatibility gaps

- The crossfade insertion point and current event priorities match upstream.
  However, exact-line matching and an internal Liquidsoap factory are version
  dependencies, not a stable public sweeper API. Keep a compatibility check against
  moving AzuraCast `main`, alongside a reproducible pinned test.
- The DOM sidebar selector matches current upstream markup. It remains an
  unofficial hook; retain browser tests for route changes and sidebar replacement.
- Media/permission checks, internal connection checks and the station adapter key
  use existing AzuraCast mechanisms. No authentication bypass was identified in
  the reviewed paths. This was source review, not a penetration test.
- Shared media storage needs an explicit policy: `intro_end` belongs to the media
  record, while vetoes, identity checks and manual protection live per station.
  Two stations sharing a media record can therefore disagree about its review.
- The panel's return link hardcodes `/station/...`, losing a deployment URL prefix.
  The sidebar injector itself handles a prefix.
- Panel data routes lack the native API exception wrapper, while the frontend
  always parses JSON. Validation/session failures can become an HTML response and
  an unhelpful JSON parse error. Test expired sessions and invalid settings.
- Crossfade-relative timing, live takeover, interruption queues, metadata
  forwarding and ducking depth still need rendered-audio tests after the blockers
  are fixed. This review does not claim they are correct merely because the source
  type-checks.

## Recommended order

1. Correct installation and add an AzuraCast boot/route smoke test.
2. Connect the actual AutoDJ callback and prove it is invoked.
3. Correct the audio graph and require a short rendered-audio runtime test in CI.
4. Add recording-identity concurrency checks and atomic review persistence.
5. Add reservation cancellation, preparation caching and deadline handling.
6. Validate timing, live switching, metadata and ducking on a disposable station.

## Resolution in the subsequent fix

The mixer now uses Liquidsoap's native compressor as a sidechain detector, with
150 ms attack and 750 ms release. Rendered synthetic playback verifies the
scheduled overlay, music reduction, audible tail and original song metadata.
The plugin replaces the generated native AutoDJ factory line so its request
callback is actually called. Background catalogue resolution removes repeated
whole-playlist work from that callback; one resolved request can take at most
one second there. A heartbeat renews 30-second reservations and reports playback
and cancellation. The plugin never counts prefetch as playback.

The installation example uses `COMPOSER_PLUGIN_MODE`. Manual and automatic
cue saves check recording identity and share a database transaction with review
metadata. A new global review row is imported from the first station's existing
JSON review when accessed; sites sharing a media library should inspect any
conflicting older per-station reviews after upgrading. The panel now displays
timing from AzuraCast's own annotation event and preserves URL prefixes.

The remaining compatibility constraints are the exact Liquidsoap configuration
lines and unofficial sidebar injection. Deployment on a live AzuraCast station
is still required to validate permissions, web UI and on-air behavior.
